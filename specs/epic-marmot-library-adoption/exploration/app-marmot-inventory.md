## 0. Architecture in one paragraph
Composition root is `src/context/MarmotContext.tsx` (3096 lines, `MarmotProvider` 795-3040) - a god-component that (i) builds the `MarmotClient` (1318-1335), (ii) starts the kind-1059 Welcome subscription (`startWelcomeSubscription` 65-90, call ~1385), (iii) per group runs an effect (1670-2166) that wires: `EpochResolver` -> write-ahead `rumorJournal` -> library emits `authenticatedApplicationMessage` -> `applicationRumorDispatcher` (FIFO queue, LRU dedup, ack) -> handlers in `registerHandlers.ts` (chat 9, reaction 7, profile 0, profile-request 30, poll 10/11/12, leave 13, delete/edit 5). `src/lib/marmot/*` are mostly DI-injected "Impl" modules with a zero-context-import rule (AC-BOUND-1, e.g. leaveGroupImpl.ts:1-12, renameGroupImpl.ts, grantAdminImpl.ts, cancelInvitationImpl.ts). Paradigm: mixed - React context as composition root + ports-and-adapters-flavoured DI for impls + event-driven pipeline (EventEmitter -> queue). `ChatStoreContext`/`PollStoreContext` do NOT call `useMarmot()`; they receive a `MarmotGroup` prop obtained by `pages/groups.tsx:533` via `getGroup()` and each carry a DUPLICATE `sendRumorSafe` (ChatStoreContext.tsx:64-82, PollStoreContext.tsx:96-113) plus rumor builders.
